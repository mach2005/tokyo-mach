# 東京真隼（TOKYO MACH）プロジェクト開発ルール

## 1. 文字コードの絶対ルール (UTF-8 厳守)
- **PowerShellの操作禁止**: PowerShellの `Set-Content`, `Get-Content`, `>`, `>>` は UTF-16LE に変換され文字化けを引き起こすため、絶対に使用しないこと。
- **編集ツールの限定**: ファイルの書き換えは必ず AI専用編集ツール（`replace_file_content` 等）または Python (`open(..., encoding='utf-8')`) で行うこと。

## 2. データ更新とビルド同期
- 選手データ変更時は、`develop/gen_songs.py` の更新とともに `HP/songs.html` や FightSong 配下のHTMLも同期・置換すること。
- 試合日程データ変更時は、`develop/data.txt` の更新に加え、`develop/build_pages.py` の `schedule_content` も同期させること。

## 3. デザイン・表示検証
- モバイル表示最適化の際、既存の文字情報やロゴを無断で非表示（`display: none` 等）にしないこと。
- スケジュールナビゲーションの矢印は「黒カプセル型（ピル形状）」を維持すること。
- 変更後はローカル表示確認およびリンク整合性のチェックを実施すること。

## 4. 自動更新スクリプトとデザイン保全
- `update_game_result.py` 等の自動更新スクリプト内のHTMLテンプレートは、常に最新の正解デザイン（NEXT VISITOR バッジ等）を完全保持させること。
- スクリプト実行により旧デザイン（LATEST VISITOR 等）へ戻すデグレードを絶対に起こさないこと。

## 5. 編集前の事前自動バックアップと即時復元
- **事前バックアップの義務**: HTMLファイル群に修正や変更を加える前に、必ず `python develop/backup_manager.py` を実行して直前状態を `archive/backup/` に自動保存すること。
- **「元に戻して」への即時対応**: ユーザーから「戻して」「ロールバック」と言われた場合は、即座に `/restore` ワークフロー（`python develop/backup_manager.py restore`）を実行し、修正前の状態に一瞬で戻してデプロイまで完遂すること。

## 6. 対話・指示ログの永続化と過去の指摘の絶対遵守
- **会話ログの自動保存**: ユーザーとのやり取りや指示はすべて `archive/chat_history/` に自動テキスト抽出して永久バックアップすること。
- **指示の重複防止・学習の維持**: 過去にユーザーから指摘・指示された事項（デザインの好み、表記ルール、修正手順等）はすべて学習・厳守し、一度言われた失敗や指摘を別セッションで二度と再発させないこと。
